FOUR PRACTICAL JOURNEYS

Prove the outcome, not just the setup.

Each path ends with a check that can fail.

01 / RECOVER

Can we get the data back?

  1. Make a consistent SQLite snapshot while the service stays online.
  2. Encrypt it using a versioned key held in OCI Vault.
  3. Upload to a private Object Storage bucket under a unique name.
  4. Download, authenticate, decrypt and restore into an isolated location.
  5. Compare integrity and owned-record counts; record restore time and snapshot age.

Proof: a verified restore—not an “upload succeeded” message. The live database is never overwritten by a drill.

02 / DETECT

Will someone know?

  1. Probe service health without generating an AI answer.
  2. Publish bounded, low-cardinality datapoints to OCI Monitoring.
  3. Evaluate health, backup-freshness and missing-data conditions.
  4. Send an alarm through Notifications to a confirmed subscriber.
  5. Use a separately labeled test signal to demonstrate firing and recovery.

Proof: a received notification and recovery transition—not just a configured alarm. Tests do not stop the model.

03 / TRACE

Where did the time go?

  1. Attach one trace ID to a real assistant request.
  2. Represent retrieval, admission and model streaming as timed spans.
  3. Export an allowlisted, bounded sample over HTTPS to Always Free APM.
  4. Find the trace by ID and compare it with the request receipt.
  5. Distinguish gateway timing from engine prefill/decode measurements.

Proof: a queryable stored trace—not merely an exporter response. No fabricated GPU or token-level spans.

04 / REPRODUCE

Can we explain every change?

  1. Keep supporting infrastructure definitions in Git.
  2. Validate Terraform and inspect the exact plan.
  3. Apply only approved reliability resources with protected state.
  4. Verify actual limits, private access and service outputs.
  5. Run drift detection; review differences before any correction.

Proof: a reviewed, reproducible resource set—not a screenshot of a console. The existing shared VM stays outside this stack.

What this does—and does not—prove.

Backups, traces and alerts strengthen the service's operating story. They do not create high availability, guarantee free capacity, improve model answer quality or turn CPU RAM into GPU HBM.

Private access, narrow permissions, bounded data collection and explicit release evidence are part of the architecture. A configured integration is not automatically a verified integration.
