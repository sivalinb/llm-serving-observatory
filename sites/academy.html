LEARN BY CHANGING ONE ASSUMPTION

Four what-if exercises.

All values are hypothetical and computed in your browser. Nothing is sent to a model, OCI or a telemetry service. These are not performance benchmarks.

Exercises do not save progress. Inputs and quiz answers disappear on reload. Runbook tasks that require a model or infrastructure are separate.

A

What fits in memory?

Dense / GQA KV capacity estimate on one device, without model sharding.

Analytical budget

Weights = parameters × bits ÷ 8. KV = 2 × layers × KV heads × head dimension × tokens × sequences × KV bytes.

Reserve is user-supplied. This omits allocator fragmentation, quantization metadata, cache sharing and architecture-specific compression. GiB means 2³⁰ bytes. No throughput or GPU utilization is predicted.

B

Where does first-token time go?

Separate queue, uncached prompt work, optional handoff and first output.

Illustrated latency budget

Uncached prompt work = input × (1 − hit fraction) ÷ assumed rate. Transfer = setup + payload ÷ bandwidth, only for disaggregated mode.

Serial, no-overlap teaching model: fixed rates, no compute contention, no network transit to the browser and no cache-lookup cost. A full cache hit does not imply zero real prefill. Payload is independent of the cache slider; a receiver may still need all prompt state. Real systems may overlap work.

C

Count tokens without double-counting.

A reported subset belongs inside its parent category.

Hypothetical reported ledger

Total = input + output. Cached input is not added again; reasoning is not added again. Remaining output is only a visible-output estimate under this simplified ledger's assumption that there are no other output categories.

Unknown subsets remain unknown. Provider-specific multimodal, draft, accepted/rejected or billing categories need their own documented contract.

D

More traffic is not always more useful work.

A deterministic FIFO toy queue with 24 arrivals and fixed work per request.

Simulated finite-run result

Each admitted request uses 200 ms prefill, then 32 visible tokens with 20 ms per generation step. TTFT = wait + 220 ms; service time = 840 ms. Requests beyond the queue bound are rejected, not silently lost.

Not continuous batching, not an engine capacity prediction. Slots have independent fixed rates. Goodput requires both latency targets; answer quality is not modeled. Cost includes the entire run, including idle and rejected-work time, at your hypothetical rate. It is not an OCI price quote.

TURN LEARNING INTO EVIDENCE

Your capstone: a small, inspectable service.

Start with the local CPU profile. Add a threat model, versioned artifacts, real receipts, a workload/SLO report, held-out quality checks, a restore drill and cost assumptions. Move to OCI only after checking Phoenix eligibility and available capacity. A GPU cluster is an optional next stage, not a prerequisite.
